# 《麦门税法》全文与算例

> 本税法为虚构娱乐规则，不属于任何真实税种，不产生任何缴费义务。

## 第一章 税目

### 第一条 基础合并税

凡向主干合并代码者，征巨无霸一只。不问代码多寡，不问作者资历。

> 设计意图：让"合并"这个动作本身被看见。零改动的 typo 修正也要盖章。

### 第二条 代码量税

变更行数（新增 + 删除）每满五百行加征一只，至多五只。

计算式：

```
T2 = min(floor((additions + deletions) / 500), 5)
```

注意两件事：

1. 分子是**新增与删除之和**。删掉 500 行祖传代码和新增 500 行脚手架，税额相同——
   因为"改动量"对评审者的负担是一样的。
2. 删除多于新增会触发第六条负熵减免，那是**另一件事**，不在此条重复优惠。

### 第三条 文件数税

改动的文件每满十个加征一只，至多三只。

```
T3 = min(floor(changedFiles / 10), 3)
```

> 设计意图：单文件大改是"深度"，多文件小改是"广度"，两者对注意力消耗的方式不同，
> 所以分别计征，互不替代。

### 第四条 周五夜间附加税

周五十八时整及之后合并者，税额倍征，并附薯条一份。

| 项 | 值 |
| --- | --- |
| 触发 | `weekday === 周五 && hour >= 18`（按配置时区） |
| 倍数 | ×2 |
| 配菜 | 薯条 ×1，商品编码 `4810` |

> 十八时整即生效，不是"十八时之后"。周五 23:59 仍算第四条；周六 00:00 起转第五条。

### 第五条 周末加班附加税

周六或周日合并者，加征五成，并附麦咖啡美式一杯。

| 项 | 值 |
| --- | --- |
| 触发 | `weekday === 周六 或 周日` |
| 倍数 | ×1.5 |
| 配菜 | 麦咖啡美式 ×1，商品编码 `507411` |

第四条与第五条**互斥**，不会同时出现。

### 第六条 负熵减免

删除行数多于新增行数，且变更总量不少于五十行者，减半征收。

```
触发条件： deletions > additions 且 (additions + deletions) >= 50
倍数：     ×0.5
```

> 设计意图：重构比堆代码更费心血。但设了 50 行门槛，避免"删了 3 行加了 2 行"也来申请减免。

### 第七条 破产保护

应纳额四舍五入取整；不足一只者按一只起征；逾十二只者按十二只征收。

```
raw    = 加性小计 × 全部乘数之积
应纳   = round(raw)
最终   = min(max(应纳, 1), 12)
```

上限可通过 `max-burgers` 输入调整，默认 12。

## 第二章 计算顺序

顺序是法律的一部分，不能随意调换：

```
① 加性小计 = T1 + T2 + T3
② 连乘     = Π(所有触发的乘数)
③ 应纳     = round(加性小计 × 连乘)
④ 最终     = clamp(应纳, 1, 12)
```

乘数之间可交换（乘法），但**打印顺序固定**为：第四条/第五条 → 第六条。

## 第三章 算例

### 算例一：周五夜间的大型重构

| 输入 | 值 |
| --- | --- |
| 新增 / 删除 | 180 / 320 |
| 变更文件 | 12 |
| 合并时间 | 周五 19:04 |

```
T1 = 1
T2 = floor((180+320)/500) = floor(1.0) = 1
T3 = floor(12/10) = 1
加性小计 = 3

M1 = ×2（周五夜间）＋ 薯条 ×1
M3 = ×0.5（删 320 > 增 180，总量 500 ≥ 50）
连乘 = 2 × 0.5 = 1

应纳 = round(3 × 1) = 3
最终 = 3 只 ＋ 1 份薯条
```

实际核价（上海人民广场，门店 1450713，预约 11:30 取餐）：

| 商品 | 数量 | 单价 | 小计 |
| --- | --- | --- | --- |
| 巨无霸 | ×3 | ¥25.50 | ¥76.50 |
| 中薯条 | ×1 | ¥13.50 | ¥13.50 |
| **应付** | | | **¥90.00** |

### 算例二：周日的线上救火

| 输入 | 值 |
| --- | --- |
| 新增 / 删除 | 96 / 31 |
| 变更文件 | 4 |
| 合并时间 | 周日 02:40 |

```
T1 = 1
T2 = floor(127/500) = 0
T3 = floor(4/10) = 0
加性小计 = 1

M2 = ×1.5 ＋ 麦咖啡美式 ×1
连乘 = 1.5

应纳 = round(1 × 1.5) = round(1.5) = 2
最终 = 2 只 ＋ 1 杯麦咖啡美式
```

核价：`2 × 25.50 + 11.90 = ¥62.90`。

注意 `round(1.5) = 2`：这是"四舍五入"，不是"向上取整"，
但在这个点上两者结果相同，容易误以为实现错了。

### 算例三：触及破产保护

| 输入 | 值 |
| --- | --- |
| 新增 / 删除 | 8400 / 6200 |
| 变更文件 | 210 |
| 合并时间 | 周五 21:10 |

```
T1 = 1
T2 = min(floor(14600/500), 5) = min(29, 5) = 5
T3 = min(floor(210/10), 3) = min(21, 3) = 3
加性小计 = 9

M1 = ×2
应纳 = round(18) = 18
最终 = min(18, 12) = 12 只 ＋ 1 份薯条
```

票面打印「破产保护 · 已达上限 12 只」。

### 算例四：负熵减免后不足一只

| 输入 | 值 |
| --- | --- |
| 新增 / 删除 | 10 / 45 |
| 变更文件 | 0 |
| 合并时间 | 周三 14:20 |

```
T1 = 1，T2 = 0，T3 = 0
加性小计 = 1
M3 = ×0.5（删 45 > 增 10，总量 55 ≥ 50）
应纳 = round(0.5) = 1
最终 = 1 只
```

`round(0.5)` 在 JS 里是 1（向正无穷方向取半）。若未来改成 `Math.floor`，
这里会变成 0，然后被第七条的"下限 1"抬回 1——两条规则共同保证了"永远至少一只"。

## 第四章 计税输出结构

```js
{
  bigMacs: 3,              // 破产保护后的最终只数
  rawBigMacs: 3,           // 四舍五入前
  capped: false,           // 是否触及上限
  floorApplied: false,     // 是否触发下限
  subtotalUnits: 3,        // 加性小计
  totalMultiplier: 1,      // 乘数连乘
  unitLines: [             // 加性税目
    { id: 'T1', label: '基础合并税', detail: '合并即征', units: 1, basis: '第一条：…' },
  ],
  multiplierLines: [       // 乘性税目
    { id: 'M1', label: '周五夜间附加税', detail: '周五19:04 合并', multiplier: 2,
      sideDish: { productCode: '4810', name: '薯条', quantity: 1 }, basis: '第四条：…' },
  ],
  sideDishes: [            // 汇总给购物篮用的配菜
    { productCode: '4810', name: '薯条', quantity: 1, reason: '周五 18:00 后合并' },
  ],
  stats: { additions, deletions, changedFiles, localTime, weekdayCn, … },
}
```

每行都带 `label` + `detail`（另有 `basis` 法条），所以税单表格与 ASCII 小票
都可以直接从这份结构渲染，不需要二次翻译。
